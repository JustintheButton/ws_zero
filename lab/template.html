Can Claude write a chess network's first weights?

We are building a small AlphaZero for chess from scratch. Then we test whether starting it from weights that Claude writes by hand, instead of random numbers, makes it learn faster. This page gains a section each time a phase passes its gate.

    Phase 2 · gate passed

    What the network sees, and how a move becomes a number

    The network never sees a chessboard. It gets 119 stacked 8×8 grids of 0s and 1s, always from the side to move's seat, and answers with a score for each of 4,672 possible moves.     Phase 3

    Teaching the network who is winning

    For every position the network gives two answers: how promising each move looks, and who is winning. Moves were easy. Judging the position nearly failed: AlphaZero's design relies on batch norm, which this experiment removes in every arm, and without it one on/off switch in the "who is winning" part shut off for good. The test that caught it trained on 16,384 positions from games and was scored on 2,048 it never saw.

    Error of the "who is winning" answer

    Original design: all three random starts stopped learning within 300 steps. With the switch removed (approved 8 Nov), all three learned. Lower is better; 0.52 is a network that always says "equal".

    What 1,000 self-play games cost on Modal

    One training run per GPU, 200 searches per move; the range runs from games averaging 340 moves to games hitting the 512-move cap. The search's own bookkeeping is added in Phase 4. For comparison, the Mac manages about 350–520 games an hour.

    The rare runaway step, and a cap on step size

    Every so often one training step is far larger than the rest and pins the "who is winning" answer at "certain win" or "certain loss" for every position, where it gets stuck. Overnight, 3,000 steps per run, three random starts each, with and without a cap on how large one step may be.

    "Who is winning" error: 0 is perfect, about 1.6 is stuck. Move error: lower is better. The memorization test is the Phase 3 gate (move error under 0.05, "who is winning" error at most 0.01). A cap of 5 stops the runaway everywhere but slows move learning in real-style training; whether to add one is Justin's call.

    Phase 1 · approved 8 Nov 2026

    The plan, frozen before any results

    Three ways to start the same network. Same code, same settings, same evaluation; only the starting weights differ. Each is trained five times with different seeds.

    Random start

    Standard random weights. The baseline that AlphaZero itself used.

    Claude writes the weights

    Claude sets all 570,379 numbers directly, with no training. It may test its network up to 50 times against practice bots or on positions it picks.

    Claude writes a heuristic

    The control. Claude writes its chess knowledge as a Python evaluator instead, and the network is trained to copy it before self-play begins.

    Network
    6 residual blocks × 64 filters, no batch norm, 570,379 weights
    Search
    About 200 simulations per move, AlphaZero's exploration formula
    Headline measure
    Self-play games needed to reach the finish line
    Finish line
    Score 50% against a fixed Stockfish level, set by a calibration run
    Verdict
    One-sided Mann–Whitney test, 5 runs against 5, at p < 0.05
    Compute
    Modal GPUs, planned at $192 or less of a $240 cap
